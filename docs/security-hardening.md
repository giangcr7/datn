# Security hardening

## Scope

The security update preserves existing accounts, diploma records, source workbooks,
signed PDFs, certificates, signing keys and the Fabric ledger. It does not reset
passwords or bootstrap business data. No database migration is needed for these
changes: refresh-session families and their indexes already exist.

## Authentication and recovery

- Every new access token carries a session-family identifier. The API requires an
  unrevoked, unexpired refresh session in that family, belonging to the same account
  and membership, and checks the current account session version and permissions.
- Logout serializes against refresh rotation and revokes the whole device family.
  An access token from that device stops working after the server processes logout;
  unrelated devices are not logged out. Password change and logout-all still revoke
  all devices. Refresh-token reuse detection remains enabled.
- Access tokens issued before this update are rejected because they have no family
  identifier. Users must sign in again after deployment.
- A mandatory password change is enforced by the JWT guard, not just the UI. Only
  the current profile, self-service password change and logout-all are allowed
  through that guard until recovery is complete. Public login, refresh, logout and
  student activation remain available under rate limits. There is no public
  privileged-account registration or password-reset bypass.
- New passwords require at least 15 Unicode code points and at most 72 UTF-8 bytes,
  preventing bcrypt truncation. A local blocklist rejects known common passwords
  and trivial repetition. Existing password hashes are not rewritten. This is not
  an exhaustive breached-password database, and MFA is not added by this update.

## Request limits and proxy configuration

Authentication budgets use a hash of the normalized target email; authenticated
API budgets use the cryptographically verified account identity. Refresh requests
use a hash of the opaque refresh token. Raw emails and tokens are not used as
stored rate-limit keys. Forged JWTs and arbitrary forwarded headers are not trusted.
A separate 300 requests/minute/IP budget limits aggregate authentication traffic.
Limits are currently process-local and reset on restart; a multi-instance deployment
needs shared storage such as Redis.

Proxy trust is off by default. For a deployment with a trusted ingress:

1. The ingress must overwrite client-supplied forwarding headers and the web/API
   listeners must not be publicly reachable around that ingress.
2. Set API `TRUSTED_PROXY_CIDRS` to the actual IP/CIDR ranges of trusted proxy hops,
   for example `127.0.0.1/32,::1/128` for same-host loopback hops. Do not blindly
   copy these values into a different network. Trust-all and hop-count settings
   are deliberately rejected.
3. Set web `FORWARD_CLIENT_IP=true` only in that protected deployment. It forwards
   a bounded, syntactically validated IP chain to the API. Without it, account
   budgets still distinguish users behind the web server, but the aggregate
   anonymous IP budget may be shared by those users.

## Public verification policy

Both JSON/QR and PDF endpoints apply a server-side allowlist. Successful public
responses expose the diploma holder name, program, classification, degree type,
graduation year, diploma/registry numbers, issue date and issue place. They do not
expose student codes, GPA, birth date, signer metadata, transaction identifiers,
hashes or PKI evidence. Technical evidence remains in internal verification,
authenticated records, database history and the existing blockchain workflow.

Invalid results omit diploma details. A committed supersession may retain only
the public replacement UUID so the existing replacement-verification link works.
PDF verification still checks the exact registered signed file and current version
before returning a sanitized response. Privacy filtering does not change signatures,
PDF bytes, snapshots, chain hashes or validity decisions.

## Secrets and remaining deployment requirements

Use Node.js 22.13 or newer (Node.js 24 is used for these checks). PDF.js is a
development-only report-test dependency, not shipped with the web application.
SheetJS and unused file-type/UUID dependencies have been removed. Student import
templates are generated by the authenticated API with ExcelJS, and uploads are
checked against the existing expanded-workbook size limit before parsing.

Narrow same-major overrides supply patched Multer and js-yaml versions where
Nest packages pin older versions, and the patched brace-expansion 1.x line.
The Nodemailer override also covers NextAuth's unused email-provider peer;
the application continues to use the credentials provider.

On November 4, 2026, the installed runtime dependency audit reports zero critical
and zero high findings, with eight moderate package entries in the ExcelJS
transitive dependency tree. These are not eight confirmed application exploits,
but they remain unresolved advisories. Do not downgrade ExcelJS or force
incompatible glob/minimatch/UUID major versions just to suppress the audit.

Revoke any API key previously shared in messages at the provider, issue a new key,
update the ignored web environment file, and restart the web process. Changing a
local value cannot revoke the old provider key. This update does not generate or
replace signing keys, wallet identities, environment secrets or CA certificates.

Before Internet deployment, configure HTTPS and secure deployment secrets, review
remaining dependency advisories, configure trusted proxies as described above,
and consider MFA for privileged users. Local development signing certificates do
not become production CA certificates after a dependency or UI update.

## Regression checks

- API Jest suites include session revocation, restricted-password guards, DTO and
  service password validation, real HTTP login-budget isolation, and JSON/PDF
  public response filtering.
- `node scripts/test-security-web.mjs` covers all-role password-change redirects,
  expired sessions and explicit proxy forwarding.
- `node scripts/test-auth-session.mjs` covers the existing remember/logout web
  integration with an isolated mock backend.
- Run both production builds and inspect `npm audit --omit=dev` before release.

Regression fixtures stay in memory or in task-owned OS temporary storage. They
must not issue real diplomas, modify retained PDFs or submit Fabric transactions.
